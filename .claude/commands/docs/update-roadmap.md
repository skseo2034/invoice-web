# Claude 커맨드: update-roadmap

`docs/ROADMAP.md`의 미완료 Task를 코드베이스와 git 히스토리를 바탕으로 분석하여 완료된 항목을 자동으로 업데이트합니다.

## 사용법

```
/git:docs:update-roadmap
```

## 프로세스

### 1단계: 현재 상태 파악
- `docs/ROADMAP.md` 읽기
- 미완료 Task(`- 미완료`, `[ ]`) 목록 추출
- 이미 완료된 Task(`✅ - 완료`) 목록 확인 (중복 처리 방지)

### 2단계: 완료 증거 수집 (미완료 Task마다)
각 미완료 Task에 대해 아래 순서로 증거를 수집합니다:

1. **git log 검색**: Task 번호(예: `Task 004`, `004`) 또는 핵심 키워드로 커밋 이력 검색
   ```
   git log --oneline --all | grep -i "004\|공통 컴포넌트"
   ```

2. **파일 존재 확인**: Task에서 언급된 경로/파일이 실제로 존재하는지 Glob으로 확인

3. **구현 코드 검색**: Task에서 요구하는 핵심 함수명, 컴포넌트명, 설정값을 Grep으로 검색

### 3단계: 변경 사항 보고 (수정 전 필수)
증거가 충분한 Task 목록을 사용자에게 먼저 보고합니다:

```
다음 Task를 완료로 표시하려고 합니다:
- Task 004: 공통 컴포넌트 구현 (근거: src/components/... 파일 존재, 커밋 "✨ feat: 공통 컴포넌트 추가")
- Task 005: 견적서 목록 페이지 UI (근거: invoice-list.tsx 구현, TanStack Query 사용 확인)

계속 진행할까요?
```

### 4단계: ROADMAP.md 업데이트
승인 후 아래 규칙에 따라 Edit 도구로 수정합니다:

**Task 라인 업데이트**:
- `- **Task NNN: 제목** - 미완료` → `- **Task NNN: 제목** ✅ - 완료`
- `- **Task NNN: 제목** - 우선순위` → `- **Task NNN: 제목** ✅ - 완료`

**서브아이템 업데이트** (해당 Task가 완료될 때만):
- `  - [ ] 설명` → `  - ✅ 설명`

**MVP 체크리스트 업데이트** (관련 기능이 구현되었을 때):
- `- [ ] 항목` → `- [x] 항목`

**Phase 헤더 업데이트** (Phase 내 모든 Task가 완료된 경우에만):
- `### Phase N: 제목` → `### Phase N: 제목 ✅`

**변경 이력 추가** (변경이 발생한 경우):
- 현재 날짜와 버전을 증가하여 변경 이력 테이블 맨 아래에 행 추가
- 형식: `| YYYY-MM-DD | X.X.X | Task NNN, NNN 완료 표시 | AI 아키텍트 |`

## 판단 기준

| 증거 수준 | 처리 |
|-----------|------|
| 관련 파일 존재 + 커밋 이력 모두 있음 | ✅ 완료 처리 |
| 관련 파일만 존재 (커밋 없음) | ✅ 완료 처리 |
| 커밋만 있고 파일 미확인 | 사용자에게 확인 후 처리 |
| 증거 없음 | 미완료 유지 (건드리지 않음) |

## 주의사항

- 이미 `✅ - 완료`인 Task는 재처리하지 않음
- 증거가 불충분한 Task는 절대 완료 처리하지 않음
- Task의 모든 서브아이템이 실제 구현되었을 때만 Task를 완료로 표시
- Phase 완료 여부는 해당 Phase의 Task가 **모두** ✅일 때만 적용
- 변경 없이 종료되는 경우 사용자에게 "변경할 항목 없음" 알림
