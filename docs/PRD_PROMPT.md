## 🤖 AI 프롬프트 (아래부터 AI에게 전달)

---

당신은 **시니어 프로덕트 매니저 겸 풀스택 개발자**입니다.
아래 프로젝트 컨텍스트를 바탕으로 **즉시 개발에 착수할 수 있는 수준의 MVP PRD**를 작성해주세요.

### 기술 스택 (고정)

- **프레임워크**: Next.js 15 App Router (TypeScript)
- **UI**: shadcn/ui (New York 스타일) + Tailwind CSS v4
- **상태 관리**: TanStack Query v5
- **폼**: react-hook-form + Zod v4
- **데이터 소스**: Notion API (공식 `@notionhq/client`)
- **PDF 생성**: `@react-pdf/renderer` (클라이언트 사이드) 또는 `puppeteer` (서버 사이드) — PRD에서 추천 방식 명시
- **배포**: Vercel

### 라우트 그룹 아키텍처 (고정)

```
(marketing)/   → 공개 랜딩 페이지
(app)/         → 어드민 대시보드 (/dashboard/**)
(auth)/        → 로그인 페이지
(invoice)/     → 공개 견적서 뷰어 (/invoice/[token])
```

## 1. 프로젝트 개요

- **서비스 한 줄 설명**: 무엇을 왜 만드는가
- **핵심 가치 제안**: 기존 방식(이메일 첨부 PDF) 대비 차별점 3가지
- **MVP 목표**: 이 버전에서 검증하려는 단 하나의 핵심 가설
- **타겟 사용자 페르소나**: 어드민 / 클라이언트 각 1명씩 (이름, 상황, 니즈)

---

## 2. 사용자 여정 (User Journey)

두 역할의 흐름을 **단계별 번호 목록**으로 작성:

**어드민 플로우** (노션 → 발송)
1. 노션 DB에서 견적서 페이지 작성
2. ...

**클라이언트 플로우** (링크 수신 → PDF 저장)

2. ...

## 4. 페이지 및 컴포넌트 구성

각 Route에 대해:

```
/invoice/[token]          → 공개 견적서 뷰어
  - 접근 방식: URL 토큰 기반 (비로그인)
  - 주요 컴포넌트: InvoiceHeader, LineItemsTable, TotalSummary, PdfDownloadButton
  - 데이터 소스: Notion API (서버 컴포넌트에서 fetch)
  - 상태: 로딩 스켈레톤, 만료/존재하지 않음 에러 페이지

/dashboard/invoices       → 견적서 목록
  ...

/dashboard/invoices/[id]  → 견적서 상세 + 링크 생성
  ...
```

## 5. 데이터 모델

### Notion DB → TypeScript 타입 매핑

```typescript
// 노션 필드명 → 앱 내부 타입
interface Invoice {
  id: string;            // Notion page ID
  token: string;         // 공개 URL용 고유 토큰 (UUID)
  // [프로젝트 컨텍스트의 필드를 모두 매핑]
  status: 'draft' | 'sent' | 'viewed' | 'approved';
  expiresAt: Date | null;
  createdAt: Date;
}

interface LineItem {
  // 항목별 데이터
}
```

### 토큰 관리 전략
- 토큰 생성 위치 (Notion 필드 vs 앱 DB)
- 만료 처리 방식
- 재발급 플로우

## 6. Notion API 연동 설계

```typescript
// 주요 API 호출 패턴
// 1. 견적서 목록 조회 (어드민 대시보드)
// 2. 견적서 단건 조회 by token (공개 뷰어)
// 3. 상태 업데이트 (viewed 자동 기록)
```

- **환경변수**: `NOTION_API_KEY`, `NOTION_DATABASE_ID`
- **캐싱 전략**: TanStack Query staleTime 설정 권장값
- **Rate Limit 대응**: 재시도 로직

## 7. PDF 출력 요구사항

### 추천 라이브러리 및 근거
(프로젝트 컨텍스트와 기술 스택을 고려한 추천)

### PDF 레이아웃 스펙
- 용지 크기: A4
- 필수 포함 요소: 로고, 발행자 정보, 수신자 정보, 항목 테이블, 합계, 유효기간, 안내문구
- 선택 요소: 서명란, QR코드, 워터마크

### 구현 컴포넌트
```
src/components/pdf/
  InvoicePdf.tsx       → react-pdf Document 컴포넌트
  PdfDownloadButton.tsx → 클라이언트 다운로드 트리거
```

## 8. 비기능 요구사항

### 보안
- [ ] 공개 URL 토큰: UUID v4, 최소 32자
- [ ] 만료 시간: 기본 30일 (설정 가능)
- [ ] Rate limiting: `/api/invoice/[token]` 엔드포인트
- [ ] Notion API 키는 서버 사이드에서만 사용

### 성능
- [ ] 공개 뷰어 LCP < 2.5초 (Next.js 서버 컴포넌트 + ISR 활용)
- [ ] PDF 생성 < 5초

### 접근성
- [ ] 시맨틱 HTML 사용
- [ ] 인쇄 미디어 쿼리 (`@media print`) 스타일 지원
